# Session: 2026-05-25 — Config Audit Skill Debugging

## Contexto

Se creo la skill `janitor-config-audit` para auditar config.yaml y SOUL.md contra los assets de janitor-core. La skill se creo correctamente y paso el test dry-run, pero al invocarla via comando slash `/janitor-config-audit` fallo con:

```
Failed to load skill for /janitor-config-audit
```

## Diagnostico

El log en `~/.janitor/logs/errors.log` revelo:

```
agent.tool_executor: Tool skill_view returned error (0.01s):
{"success": false, "error": "Skill 'janitor-config-audit' is not supported on this platform.",
 "readiness_status": "unsupported"}
```

El sistema de skills tiene un check de plataforma en `skill_matches_platform` (agent/skill_utils.py) que evalua `sys.platform`. En WSL, `platform.system()` devuelve `Linux`. La skill declara `platforms: [linux, macos]` — teoricamente compatible. Sin embargo, el check interno esta devolviendo False para linux en este entorno especifico de WSL.

## Solucion aplicada

Se actualizo el SKILL.md para documentar la limitacion y el workaround: invocar el script directamente via terminal en lugar del comando slash.

```bash
python3 ~/.janitor/skills/janitor-config-audit/scripts/audit.py        # dry-run
python3 ~/.janitor/skills/janitor-config-audit/scripts/audit.py --apply  # aplicar
```

## Comparacion real de configs (sesion actual)

| Archivo | Resultado |
|---|---|
| config.yaml | IDENTICOS (salvo que activo ahora tiene seccion `janitor.language_instruction` que faltaba) |
| SOUL.md | IDENTICOS |

La unica diferencia era la falta de la seccion `janitor` en el config.yaml activo, que el usuario solicito aplicar.

## Tecnica de debugging aplicada

1. `grep -rn "Failed to load skill" janitor-core/` para localizar el origen del mensaje
2. `tail ~/.janitor/logs/errors.log` para ver el error completo con `readiness_status`
3. `grep -n "skill_matches_platform\|readiness_status\|unsupported" tools/skills_tool.py` para entender el flujo
4. `python3 -c "import platform; print(platform.system())"` para verificar sys.platform
